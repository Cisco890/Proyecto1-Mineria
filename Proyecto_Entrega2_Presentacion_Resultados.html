Actividad 5: Conjuntos de entrenamiento y prueba

Método de validación

Dado que el conjunto de datos está agregado a nivel departamental y cuenta con únicamente 22 observaciones, no es posible aplicar una partición fija tradicional de entrenamiento y prueba. Con una división estándar 80/20 el conjunto de prueba quedaría con apenas 4 departamentos, lo que haría que los resultados dependieran fuertemente de cuáles cayeron en cada partición.

Por esta razón se utilizó Leave-One-Out Cross Validation (LOOCV). En cada iteración el modelo se entrena con 21 departamentos y se evalúa en el departamento restante, repitiendo el proceso 22 veces hasta que todos los departamentos hayan sido usados exactamente una vez como prueba. Las métricas finales se calculan promediando los errores de las 22 iteraciones, lo que produce una estimación más honesta del error de generalización sin desperdiciar observaciones.

Como la variable respuesta es cuantitativa, no aplica el concepto de balance de clases. En su lugar se analiza la presencia de valores atípicos con alta influencia sobre el modelo.

Actividad 6: Preprocesamiento y preparación de datos

Esta sección describe todas las transformaciones aplicadas a los datos antes de entrenar los modelos. El resultado final es el objeto datos_modelo, que será utilizado por todos los algoritmos en las actividades 7 y 8.

Carga y filtro por año

Los archivos fuente del INE contienen registros del período 2012 a 2022. Se filtra únicamente el año 2022 para garantizar un análisis de corte transversal limpio, donde cada departamento representa una observación bajo condiciones temporales homogéneas. Mezclar múltiples años sin modelar la estructura temporal produciría conteos inflados sin interpretación válida para un modelo de regresión de corte transversal.

Función de métricas

Para mantener consistencia en la evaluación de todos los algoritmos, se define una única función de métricas que será utilizada por los cuatro modelos en las actividades siguientes:

  • MAE: error absoluto promedio en número de divorcios.
  • RMSE: penaliza más los errores grandes, útil para detectar fallos en departamentos extremos.
  • MAPE: error porcentual promedio, facilita la interpretación relativa.

Para los modelos estadísticos (Poisson y Binomial Negativa) se añaden adicionalmente AIC y BIC como criterios de selección entre variantes.

Actividad 7: Creación de modelos por algoritmos

7.1 Regresión Binomial Negativa

La Regresión Binomial Negativa es el modelo principal del análisis. Se implementan cuatro variantes con distintas combinaciones de predictores para identificar cuál logra el mejor equilibrio entre ajuste y parsimonia. Dado que el conjunto de datos tiene únicamente 22 observaciones, se evalúa cada variante mediante LOOCV en lugar de un split tradicional.

loo_nb <- function(formula_modelo, datos) {
  n            <- nrow(datos)
  predicciones <- numeric(n)

  for (i in seq_len(n)) {
    entrenamiento   <- datos[-i, , drop = FALSE]
    prueba          <- datos[i, , drop = FALSE]
    modelo          <- MASS::glm.nb(formula_modelo, data = entrenamiento)
    predicciones[i] <- predict(modelo, newdata = prueba, type = "response")
  }

  list(
    metricas     = calcular_metricas(datos$casos_divorcio, predicciones),
    predicciones = predicciones
  )
}

Se define la función loo_nb que implementa LOOCV para cualquier fórmula de Binomial Negativa. En cada iteración entrena con 21 departamentos y predice el restante, devolviendo las métricas MAE, RMSE y MAPE junto con el vector de predicciones.

formula_nb_1 <- casos_divorcio ~ casos_violencia_z + es_capital

formula_nb_2 <- casos_divorcio ~ casos_violencia_z + es_capital +
                porc_urbano_z

formula_nb_3 <- casos_divorcio ~ casos_violencia_z * es_capital

formula_nb_4 <- casos_divorcio ~ casos_violencia_z + es_capital +
                porc_urbano_z + edad_victima_prom_z

Se definen cuatro fórmulas que varían en complejidad. NB_1 es el modelo base con los dos predictores más importantes identificados en el análisis exploratorio. NB_2 agrega la proporción de urbanización. NB_3 introduce un término de interacción entre violencia y la dummy de capital para capturar si el efecto de la violencia sobre los divorcios es distinto en Guatemala respecto al interior. NB_4 es el modelo más complejo, incluyendo además la edad promedio de la víctima.

Se selecciona NB_1 como modelo final por ser el más parsimonioso con el menor MAE y AIC. Su fórmula es:

\[\log(\hat{\mu}) = \beta_0 + \beta_1 \cdot \text{casos\_violencia\_z} + \beta_2 \cdot \text{es\_capital}\]

Esta decisión prioriza la interpretabilidad y la capacidad de generalización sobre la complejidad, criterios especialmente relevantes cuando el tamaño muestral es reducido.

Modelo de referencia: Regresión Poisson

La Regresión Poisson se incluye como modelo de referencia por ser el punto de partida estadístico natural para variables de conteo. Sin embargo, la razón de dispersión obtenida confirma la presencia de sobredispersión severa, lo que viola el supuesto central de Poisson (igualdad entre media y varianza). Sus resultados se interpretan únicamente como línea base frente al modelo principal de Regresión Binomial Negativa, que parametriza explícitamente esta sobredispersión.

Esta sección no representa un cuarto algoritmo seleccionado en el proceso de modelado, sino una referencia estadística que fundamenta empíricamente la elección de la Binomial Negativa como modelo principal.

loo_poisson <- function(formula_modelo, datos) {
  n <- nrow(datos)
  predicciones <- numeric(n)

  for (i in seq_len(n)) {
    entrenamiento   <- datos[-i, , drop = FALSE]
    prueba          <- datos[i, , drop = FALSE]
    modelo          <- glm(formula_modelo, data = entrenamiento, family = poisson(link = "log"))
    predicciones[i] <- predict(modelo, newdata = prueba, type = "response")
  }

  list(
    metricas     = calcular_metricas(datos$casos_divorcio, predicciones),
    predicciones = predicciones
  )
}

loo_rf <- function(datos, mtry_valor, min_node_size_valor, num_trees_valor) {
  n            <- nrow(datos)
  predicciones <- numeric(n)

  for (i in seq_len(n)) {
    entrenamiento   <- datos[-i, , drop = FALSE]
    prueba          <- datos[i, , drop = FALSE]

    modelo <- ranger(
      casos_divorcio ~ .,
      data           = entrenamiento,
      num.trees      = num_trees_valor,
      mtry           = mtry_valor,
      min.node.size  = min_node_size_valor,
      importance     = "permutation",
      seed           = 123
    )

    predicciones[i] <- predict(modelo, data = prueba)$predictions
  }

  list(
    metricas = calcular_metricas(datos$casos_divorcio, predicciones) %>%
      mutate(
        mtry          = mtry_valor,
        min_node_size = min_node_size_valor,
        num_trees     = num_trees_valor
      ),
    predicciones = predicciones
  )
}

loo_xgb <- function(x, y, params, nrounds_valor) {
  n            <- length(y)
  predicciones <- numeric(n)

  for (i in seq_len(n)) {
    x_train <- x[-i, , drop = FALSE]
    y_train <- y[-i]
    x_test  <- x[i, , drop = FALSE]

    dtrain <- xgb.DMatrix(data = x_train, label = y_train)
    dtest  <- xgb.DMatrix(data = x_test)

    modelo <- xgb.train(
      params  = params,
      data    = dtrain,
      nrounds = nrounds_valor,
      verbose = 0
    )

    predicciones[i] <- predict(modelo, dtest)
  }

  predicciones <- pmax(predicciones, 0)

  list(
    metricas     = calcular_metricas(y, predicciones),
    predicciones = predicciones
  )
}

La función loo_xgb sigue la misma estructura que loo_nb y loo_rf: en cada iteración entrena con 21 departamentos y predice el restante, acumulando predicciones que luego se usan para calcular MAE, RMSE y MAPE. El pmax(..., 0) asegura que ninguna predicción sea negativa, lo cual no debería ocurrir con count:poisson pero se aplica como salvaguarda.
